# [V2.0.1] - Security Hardening, Server Monitoring & Automatic Login Addresses

### Fixed

- **LocalAdmin Confirmation Dialogs**: Removed HTML rendering of server names in stop, restart and related confirmation dialogs to prevent stored script injection.
- **Saved Credential Reuse**: Restricted reuse of masked database passwords and saved QQ ClientSecret values when the destination or associated identity changes.
- **Local Server Launch Validation**: Replaced executable blacklist checks with supported SCPSL executable validation and restricted server IDs to prevent log path traversal.
- **Daemon Host Validation**: Added validation of request Host headers against the configured listener and local connection address.
- **QQ Group Notification Routing**: Applied the configured group allowlist before recording groups for automatic notifications.
- **Player History and Trends**: Improved historical player statistics and trend reporting.
- **Daemon Shutdown Protection**: Improved shutdown confirmation and handling so closing the Bot remains independent of the game server lifecycle.
- **Live Database Tests**: Removed hardcoded MySQL credentials from current test sources; live tests use environment variables and are skipped by default. Removing credentials from code does not revoke credentials already disclosed.

### Changed

- **Authenticated TCP Messages**: Added HMAC authentication, timestamps and nonces with replay checks and constant-time signature comparison for Bot/plugin communication. This is authentication, not transport encryption.
- **Safer Fresh-Install Defaults**: Default listeners use loopback addresses, and shipped configuration avoids the public shared token.
- **Explicit QQ Administrator Lists**: Added `Bot:AdminUserIds` and `OfficialQq:AdminOpenIds`. When configured, these lists determine administrator access; empty lists retain legacy role/notification-list behavior for compatibility. Configure administrator and group allowlists explicitly.
- **Concise Startup Security Warning**: Simplified the warning for default or empty tokens while retaining token pairing instructions and the requirement to restrict cross-machine access.
- **Licensed Build References**: Game reference assemblies are no longer tracked in the repository; plugin builds use official NuGet API packages and locally supplied game references. Build output directories are excluded from Git.
- **Component Versions**: Updated the Bot, Daemon and Shared runtime to `2.0.1`.

### Added

- **Automatic Web Panel Login Addresses**: Detects active, non-loopback IPv4 addresses and prints usable login URLs when listening on all interfaces. Loopback listeners retain a local login URL and explain how detected LAN addresses can be enabled.
- **Server Load Overview**: Added consolidated game server load monitoring, status reporting and overview charts.
- **Security Regression Coverage**: Tests cover authentication, credential destination checks, launch validation, administrator policies and daemon Host validation.

### Validation

- Release builds of Bot, Daemon and both game server plugin variants.
- Bot unit tests; the live database test remains skipped by default.
- Release archives are built from clean publish output, excluding persistent data, local configuration overrides and game reference assemblies.

### 📦 Asset Details

- `Server_Qcha.Bot-v2.0.1.zip`: Windows framework-dependent .NET 8 bundle containing Bot, Daemon, Shared runtime, Web panel assets, default configuration and launcher scripts. Install the .NET 8 ASP.NET Core Runtime before running. Preserve your existing `data/` and configuration when upgrading.
- `Server_Qcha-EXILED.dll`: EXILED plugin built against the project's `ExMod.Exiled` 9.5.0 references. Install only the plugin DLL; the game and EXILED provide their own dependencies.
- `Server_Qcha-LabAPI.dll`: LabAPI plugin built against `Northwood.LabAPI` 1.1.7 and local game references. Install only the plugin DLL.
- `SHA256SUMS.txt`: SHA-256 checksums for the three downloadable artifacts.
