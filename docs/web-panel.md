## 为什么取代官方 LocalAdmin

### 官方 LocalAdmin 的局限性
在传统的 SCPSL 服务器运维中，服主普遍使用官方提供的 `LocalAdmin.exe`。其主要缺陷如下：
1. **纯终端黑框界面**：每个服务器实例占用一个独立黑框，集群多开时难以管理且极易误操作；
2. **缺乏远程运维能力**：必须通过 Windows 远程桌面 (RDP) 或 Linux SSH 登录服务器主机，无法在浏览器或手机上便捷管理；
3. **缺少多管理员权限划分**：任何能接触控制台的人均拥有完整的最高权限，无法分配受限角色；
4. **无历史监控数据**：无法查看历史在线人数走势、峰值统计与资源消耗曲线。

### 核心能力对比

| 运维能力 | 官方 LocalAdmin (LA) | Qridge Web 管理面板 |
|---|---|---|
| **交互媒介** | 本地命令行窗口 (CLI) | 现代 Web 控制台（PC 端 + 手机专属 UI） |
| **多服管理** | 一服一窗口，杂乱分散 | 单一控制台集中管理全服集群 |
| **远程管控** | 必须依赖 RDP / SSH | 任意设备浏览器即可访问，随时随地运维 |
| **自愈守护** | 基础崩溃退出重启 | 完备心跳状态机、静默卡死检测、重启频次限流保护 |
| **日志与控制台** | 简单黑框打印 | Web 交互控制台、环形日志缓冲区、ANSI 颜色高亮与热过滤 |
| **权限管控** | 无，全员超级管理员 | 细粒度 RBAC 权限系统，可精确授权各模块操作 |
| **运营分析** | 无 | 24 小时在线玩家动态趋势折线图、全服在线与今日峰值 |
| **操作审计** | 无 | 全局审计日志，每次操作记录时间、人员、IP 与结果 |

## LocalAdmin 托管与守护引擎原理

### 协议级底层接管
本项目并非在外部简单启动可执行程序，而是从底层完整实现了官方 LocalAdmin 与 SCPSL 服务端之间的原生通信协议：
- 主程序绑定本地随机 TCP 端口作为控制台服务端；
- 使用官方标准命令行参数拉起游戏进程：包含 `-console <port>`、`-id <process_id>`、`-heartbeat <threshold>` 等参数；
- 解析上行数据帧（标准输出行、心跳控制码），维护内存环形缓冲区；
- 将面板下发的指令以下行数据帧安全写入游戏控制台。

### 心跳状态机与静默崩溃自愈
游戏服务器在发生死锁或无响应时，进程可能并未退出，但已无法处理任何玩家请求。
系统内置完整的心跳状态机：
1. **等待首个心跳阶段**：游戏启动后给予宽限期（默认 80 秒），防止加载大地图时误判；
2. **心跳活跃期**：实时接收游戏主线程上报的心跳信号；
3. **超时判定与自愈**：一旦心跳间隔超出阈值，系统判定游戏陷入静默卡死，主动终止挂起进程并重新拉起。

### 防死循环重启限流机制
当服务端因配置损坏、插件异常等原因导致启动即崩溃时，无限制的重启可能耗尽系统资源。
系统引入了滑动时间窗口限流策略：
- 默认在 480 秒时间窗口内，最多允许连续重启 4 次；
- 一旦耗尽重启配额，系统将暂停自愈并记录严重错误状态，等待管理员人工排查，杜绝雪崩效应。

## Web 面板核心功能模块

### 1. 服务器总览 (Overview)
- **运营指标卡片 (KPI)**：实时统计全服在线总人数、今日在线峰值、纳管服务器总数；
- **24 小时在线趋势折线图**：后台定时采样真实玩家数据，精准过滤 `Dedicated Server` 虚报人数，绘制平滑的历史在线曲线；
- **服务器负载矩阵**：直观展示每个服务器的端口、运行状态、在线/上限进度条与通信延迟。

### 2. 服务器进程管理 (Local Admin)
- 提供本地托管 SCPSL 进程的图形化控制面板；
- 实时展示各实例的 PID、CPU 占用百分比、内存使用量、运行时长与心跳状态；
- 支持一键执行启动、停止、安全重启与强制终止操作。

### 3. 多服交互与实时控制台 (Servers)
- 支持选中任意服务器下发管理指令，并在界面中实时查看返回回显；
- 在线玩家弹窗穿透：点击即可查看指定服务器的所有在线玩家（昵称、角色、延迟、SteamID）；
- 快捷操作：支持直接对特定玩家执行踢出、封禁，或向全服发送广播。

### 4. 手机专属 UI 界面 (Mobile Responsive)
- 当检测到视口宽度 $\le 768\text{px}$ 时，自动激活移动端专属界面：
  - 隐藏固定侧边栏，顶栏提供触控汉堡菜单按钮；
  - 点击滑出原生 App 风格的侧滑抽屉（集成用户信息、全部功能导航与快速登出）；
  - 页面卡片自动转为 1~2 列流式排版，各类弹窗自适应为 94vw 视口宽度。

### 5. 细粒度多账号权限体系 (RBAC)
- 支持创建多个管理员账号，支持多端同时在线（电脑与手机可同时登录同一账号，互不顶号）；
- 提供模块级细粒度权限控制：
  - `servers.view`：查看服务器状态与在线情况；
  - `server.control`：向服务器发送指令、重启与关服；
  - `bot.manage`：配置与管理 QQ 机器人；
  - `logging.manage`：切换系统运行时日志级别；
  - `accounts.manage`：增删改管理员账号与权限；
  - `audit.view`：查阅系统操作审计日志；
- **会话联动安全**：当账号修改密码时，系统会自动保留当前设备，并强制踢下线该账号在其他所有设备上的会话。

### 6. 全方位操作审计日志 (Audit)
- 系统全程捕获所有管理员通过面板下发的关键指令与配置变更；
- 记录内容涵盖：操作时间、操作人账号、客户端真实 IP、操作动作、目标服务器及执行参数，确保追责有据。

### 7. 动态日志级别热切换 (Logging)
- 支持在面板中实时热切换系统日志级别（Trace / Debug / Info / Warning / Error）；
- 排查复杂问题时可临时切至 Debug 级别，排查完毕切回 Info，全程无需重启程序。
