Server_Qcha v2.4.0 将运维面板的玩家统计和数据库封禁接入游戏服。LabAPI 与 EXILED 插件都能复用面板现有的 MySQL 表，多台服可以汇总玩家记录，并执行同一份数据库封禁名单。

## 主要改动

- **多服玩家统计。** 插件将游戏时长、玩家击杀、SCP 击杀和阵亡增量写入 `PlayerData`，保留已有 QQ 绑定和管理员资料。启用「请勿追踪」的玩家不会被记录统计。
- **面板封禁在游戏服生效。** 插件检查新加入和在线玩家的完整账号 ID，例如 `76561198000000000@steam`。面板解除数据库封禁后，玩家可以重新加入。游戏原生封禁仍由游戏原生功能管理。
- **封禁期限采用数据库时间。** 面板保存和判断封禁期限时使用数据库时钟，让面板的有效状态与插件查询一致。玩家统计与 QQ 绑定统一使用 `PlayerData` 表名。

## 升级与配置

1. 将新版面板包解压到新目录，迁移原有 `appsettings*.json` 和 `data/`。在维护窗口切换守护进程，因为退出守护进程会停止它托管的游戏服。
2. 按游戏服框架部署插件，保留原插件配置。将新版 `Server_Qcha.dll` 和包内 `dependencies/` 一起放入对应的插件目录。
3. 将插件的 `database_connection_string` 指向运维面板使用的 MySQL 库。已有 `PlayerData`、`BanPlayerData` 表可直接沿用。首次部署可在面板的「数据库」页执行「一键初始化数据表结构」。
4. 如果同一台服已由其他插件向同一张表写入统计，将 Server_Qcha 的 `database_player_stats_enabled` 设为 `false`，即可避免双计并继续检查数据库封禁。

插件分别使用 LabAPI 1.1.7 和 EXILED 9.15.2 引用编译。Windows 和 Linux 主程序包通过了解压启动验证。临时 MariaDB 已验证并发统计写入、QQ 绑定、旧表兼容以及有效、过期和已解除的封禁查询。真实游戏客户端的踢出与重新加入待联机验证。[构建与测试结果](https://github.com/jikekei/Server_Qchat/actions/runs/44112736939)
