## Web 面板相关

### Q1: 手机或外部电脑无法访问 Web 面板？
1. **检查监听绑定地址**：确认 `appsettings.Local.json` 中 `WebPanel:Host` 为 `"0.0.0.0"` 而不是 `"127.0.0.1"`（后者仅允许本机回环访问）；
2. **检查安全组与防火墙**：在云服务器控制台（如腾讯云、阿里云、华为云）的安全组中，确保入站规则已放行 Web 面板端口（默认 `8080`，TCP 协议）；
3. **检查系统本地防火墙**：在 Windows Defender 防火墙或 Linux iptables/ufw 中放行对应端口。

### Q2: 初始管理员密码忘记或未保存？
1. 停止运行中的主程序；
2. 打开 `appsettings.Local.json`，确保 `WebPanel:ResetBuiltInPasswordOnStartup` 为 `true`；
3. 删除程序目录下的 `panel.db` 文件（若无其他重要自定义账号配置）；
4. 重新运行程序，控制台将重新生成并打印全新的随机管理员初始密码。

### Q3: 多个管理员同时登录会互相顶号吗？
不会。
- 系统基于全球唯一的独立 Token 维护各端会话，支持同一账号在多台电脑、平板及手机上同时在线操作；
- **安全联动机制**：仅当某个账号在某台设备上执行了“修改密码”操作时，系统才会强制使该账号在其他所有设备上的会话失效，以防密码泄露后被旧会话持续滥用。

## LocalAdmin 与服务端进程

### Q4: 为什么完全不需要再运行官方 LocalAdmin 了？
本项目从底层完整实现了官方 LocalAdmin 与游戏主程序之间的标准通信协议（通过 `-console`、`-id`、`-heartbeat` 内部通信管道）。
- 主程序具备原生 LocalAdmin 的所有核心职责：进程拉起、双向标准流重定向、心跳检测与崩溃拉起；
- 在此基础上额外提供了现代化 Web 界面、手机专属 UI、多管理员权限划分与实时运营折线图。因此您完全可以彻底告别官方黑框 LocalAdmin。

### Q5: 游戏服务崩溃后为什么没有继续自动重启？
这是系统内置的**防死循环重启限流保护**在生效：
- 系统默认在 480 秒（8 分钟）的滑动时间窗口内，最多允许自动重启 4 次；
- 若游戏因配置文件格式错误、缺少依赖或核心插件报错而在启动后连续崩溃，系统会触发限流保护并停止自动重启，防止无限崩溃耗尽服务器 CPU 与磁盘 IO；
- 请检查 `localadmin-logs/` 目录下的崩溃日志，修复游戏服本身的错误后，在 Web 面板中手动点击“启动”。

### Q6: 为什么在线统计没有把 Dedicated Server 算进去？
这是系统刻意设计的特性。在部分 SCPSL 服务端环境下，控制台会产生名为 `Dedicated Server` 的虚拟占位实体。本系统在底层解析玩家列表时已自动将其过滤，以确保总览 KPI、折线图走势及在线玩家表格展示的均为 100% 真实玩家。

## 游戏服插件与通信

### Q7: 面板执行指令提示 Unauthorized 或连接超时？
1. **Token 不匹配**：检查游戏服插件配置文件中的 `auth_token` 与主程序中的 `SocketServer:AuthToken` 是否完全一致（区分大小写，两边必须完全相同）；
2. **端口占用或未配置**：检查插件的 `tcp_port` 是否与主程序 `SocketServer:Ports` 中的端口一一对应；
3. **跨机部署网络不通**：若游戏服与主程序不在同一台机器，请确保游戏服所在机器的防火墙已放行插件对应的 TCP 端口。

### Q8: 游戏内输入 .ac 后 QQ 群没有收到通知？
1. **检查目标群号**：确认 `appsettings.Local.json` 中 `Bot:AcTargetGroupId` 填写了正确的 QQ 群号（非 0）；
2. **检查通知外连端口**：游戏服插件配置中的 `bot_ip` 与 `bot_port` 必须指向主程序所在的 IP 和通知接收端口（默认 `10088`）；
3. **检查主程序通知端口入站**：若主程序部署在云服务器，需在云服务器安全组中放行 `10088` 端口（TCP）的入站访问。

## QQ 机器人联动

### Q9: 机器人对群里的任何指令均无反应？
1. **检查 WebSocket 状态**：确认 NapCatQQ / OneBot 框架已正常登录，且正向 WebSocket 服务端已启动（默认端口 6700）；
2. **检查群白名单**：检查 `Bot:AllowedGroupIds` 配置。如果数组不为空，则机器人只会响应白名单列表内的群消息；
3. **查看主程序日志**：在主程序控制台或 Web 面板的“日志级别”中将日志切换为 `Debug`，查看是否有接收到群消息事件的上报。
