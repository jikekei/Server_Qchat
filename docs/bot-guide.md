# QQ 机器人与群服联动指南

Server_Qcha (Qridge) v2.0 提供了功能完备的社群机器人与游戏服联动引擎。系统同时支持 **QQ 官方机器人开放平台 (OpenAPI v2)** 与社区主流的 **NapCatQQ (OneBot 11)** 双协议引擎，并支持在 Web 管理面板中进行在线无缝热切换。

## 双引擎架构与特性对比

为了满足不同服主的合规与运维需求，系统实现了一套统一的指令分发总线，下接两种完全不同的通信协议引擎：

| 特性维度 | QQ 官方机器人开放平台 (OpenAPI v2) | NapCatQQ (OneBot 11) |
|---|---|---|
| **接入协议** | 腾讯官方 OpenAPI v2 + WebSocket | OneBot 11 正向 WebSocket |
| **封号风险** | 零风险，官方合规开放接口 | 依赖第三方 NTQQ 框架模拟协议 |
| **群聊触发方式** | 群内必须 @机器人 发送指令 | 直接发送文本或前缀触发，无需 @ |
| **官方快捷面板** | 支持直接生成腾讯官方快捷指令输入面板 (/v2/panels) | 不支持官方输入面板 |
| **权限控制** | 官方面板直接识别 `only_admin`，管理员专享 | 机器人在代码层根据群成员身份校验权限 |
| **消息限制** | 严格遵循官方频次限额，长消息自动智能分段 | 限制较宽松，可直接发送较长文本 |
| **适用人群** | 追求永久合规、长久稳定的大型社区与公服 | 习惯无 @ 触发体验、已部署 OneBot 生态的服主 |

## 方案 A：QQ 官方机器人 (推荐合规方案)

### 1. 开放平台准备工作
1. 访问 [QQ 开放平台](https://q.qq.com/) 注册并登录开发者账号；
2. 在「应用管理」中创建机器人应用，选择绑定群聊/私信场景；
3. 获取机器人的 **AppID** 与 **AppSecret (ClientSecret)**；
4. 若机器人处于测试阶段，在开放平台中将当前测试 QQ 群或测试人员加入沙箱白名单。

### 2. 配置文件设置
在 `appsettings.Local.json`（或 `appsettings.json`）中配置：
```json
{
  "Bot": {
    "Mode": "Official"
  },
  "OfficialQq": {
    "ApiBase": "https://api.bot.qq.com",
    "AppId": "102xxxxxx",
    "ClientSecret": "your_client_secret_here",
    "Sandbox": false,
    "Intents": 33554432,
    "MaxTextLength": 800,
    "AllowActivePush": false,
    "AdminOpenIds": [],
    "AllowedGroupOpenIds": [],
    "AcTargetGroupOpenId": ""
  }
}
```

配置说明：
- `Mode`：设为 `"Official"` 启动官方引擎；
- `AppId` / `ClientSecret`：开放平台申请的开发者凭证；
- `Sandbox`：若在沙箱环境测试，请设为 `true`；生产上线后设为 `false`；
- `Intents`：默认 `33554432`（群聊与单聊消息事件感知）；
- `MaxTextLength`：单条消息最大字数上限，默认 800 字，系统会自动进行智能分段下发。

### 3. 官方指令面板 (/v2/panels) 自动注册
QQ 官方机器人支持在聊天框直接展示结构化的指令选项。系统内置了官方面板适配引擎：
- 自动提取系统中的全部标准指令，裁剪符合腾讯规范的名称（不超过 14 字符）与描述（不超过 30 字符）；
- 对管理员敏感指令（如 `/bc`、`/round`、`/ban`、`/setadmin`）自动标记 `only_admin: true`，普通群员在面板中不可见；
- 管理员可在 Web 控制面板的设置页面中一键点击「同步指令面板」，将最新的指令规格下发至腾讯开放平台；亦可随时查看当前在线注册的面板数据或一键清空重置。

### 4. 群聊与私聊交互特性
- **群聊消息**：根据腾讯官方规范，群成员必须在消息中 `@机器人`，后接具体指令（如 `@机器人 cx`）。
- **私聊消息**：直接向机器人发送指令文本即可，无需 @ 符号。
- **被动回复配额**：官方协议要求所有群消息回复携带 `msg_id` 与自增 `msg_seq`，系统底层已完全托管回复生命周期与重试机制。

## 方案 B：NapCatQQ (OneBot 11 传统方案)

### 1. NapCatQQ 配置
1. 部署并启动 NapCatQQ 客户端（登录专用运维 QQ 账号）；
2. 进入 NapCat 网络配置，启用 **WebSocket 服务端（正向 WS）**：
   - 监听地址：`127.0.0.1`
   - 监听端口：`6700`
   - Access Token：若设置了 Token，需在客户端中同步配置。

### 2. 机器人端连接设置
在 `appsettings.Local.json` 中配置：
```json
{
  "Bot": {
    "Mode": "NapCat",
    "AllowedGroupIds": [ 123456789 ],
    "AcTargetGroupId": 123456789
  },
  "GoCqHttp": {
    "WsBaseUri": "ws://127.0.0.1:6700",
    "ReconnectDelaySeconds": 5,
    "MaxReconnectDelaySeconds": 30
  }
}
```
配置说明：
- `Mode`：设为 `"NapCat"`；
- `WsBaseUri`：填写 NapCat 监听的正向 WebSocket 完整地址；
- `AllowedGroupIds`：允许响应的 QQ 群白名单。留空数组 `[]` 表示响应机器人加入的所有群；
- `AcTargetGroupId`：接收游戏内报警求助消息的目标群号。

## Web 面板在线热切换引擎

进入 Web 管理控制台的「系统设置」或「机器人管理」页面：
1. 可实时查看当前机器人引擎类型（NapCat 或 Official）、连接健康状态与延迟；
2. 在下拉框中选择要切换的目标引擎（`NapCat` / `Official` / `Both` / `None`）；
3. 点击「保存并应用」后，系统将在后台自动断开旧连接、启动新协议引擎、刷新订阅并完成健康检查；
4. **全程无需重启 Bot 主程序**，真正实现零宕机平滑切换。

## QQ 联动指令大全

### 玩家查询与绑定指令
面向群内所有玩家开放，提供即时状态检索：

| 指令 | 说明 | 示例 | 回显说明 |
|---|---|---|---|
| `help` 或 `/help` | 查询机器人所有可用指令列表 | `help` | 返回结构化的指令速查帮助文本 |
| `cx` 或 `/cx` | 查询全部纳管服务器的在线人数与状态 | `cx` | 显示各服名称、在线人数/最大上限及网络延迟 |
| `info` 或 `/info` | 查询当前服务器的基础配置与系统说明 | `info` | 返回服务器介绍、规则摘要与版本状态 |
| `#<服号>` | 穿透查看指定服务器当前全部在线玩家详情 | `#1` | 列出该服全部在线玩家的昵称、角色组、SteamID 与 Ping |
| `/bd <Steam64>` | 将发送者的 QQ 账号与指定的 Steam64 ID 绑定 | `/bd 76561198000000000` | 校验通过后记录至数据库，提示绑定成功 |
| `/me` | 查询本人绑定的 Steam 游戏历史战绩与游玩统计 | `/me` | 统计并返回游戏时长、阵营胜率与战绩数据 |

### 管理员运维指令
仅限群主、群管理员或在配置中指定了权限的管理员执行：

| 指令 | 说明 | 示例 | 行为说明 |
|---|---|---|---|
| `/bc <服号> <内容>` | 向指定游戏服发送全服广播公告 | `/bc 1 服务器将于10分钟后更新` | 游戏内全体在线玩家屏幕中央弹出广播提示 |
| `/round <服号>` | 强制重置/重启指定服务器当前对局回合 | `/round 1` | 向游戏服下发 rest 指令，立即重新开局 |
| `/ban <服号> <ID> <时长> <原因>` | 踢出或封禁游戏内的违规玩家 | `/ban 1 3 120m 违规卡BUG` | 向游戏服下发惩处指令并即时生效 |
| `/setadmin <服号> <ID> <组名>` | 为当前对局中的指定玩家分配临时管理组 | `/setadmin 1 3 admin` | 赋予指定玩家当局的管理组权限 |

## 游戏内实时报警推送 (.ac)

系统支持玩家直接在游戏内向 QQ 管理群发起一键求助或举报违规：
1. 玩家在游戏内按下 `~` 键唤出控制台；
2. 输入 `.ac <详细原因>`，例如：
   ```text
   .ac 发现B层有疑似透视外挂，请管理员上线核查！
   ```
3. 游戏服务端插件通过异步轻量 TCP 长连接，在 50 毫秒内将事件推送至 `Server_Qcha.Bot`；
4. 机器人根据配置的 `AcTargetGroupId`（或官方 OpenId）立即向管理群推送图文告警通知，同时附带举报人信息、所在服务器与时间；
5. 游戏内所有在线管理员的屏幕上亦会同步弹窗显示持续 10 秒的广播告警，形成线上线下双重联动。

## 数据互通与战绩持久化

当主程序配置了 MySQL 数据库连接（`MySql:ConnectionString`）时：
- 玩家数据绑定表（`qq_steam_binding`）与游玩历史统计表将由系统自动托管；
- 玩家在群内绑定后，数据跨服漫游共享，服主无需手动导入或同步；
- 管理员可通过 Web 面板的「数据库管理」模块直接搜索、修改或解绑特定数据，保障数据资产安全。
